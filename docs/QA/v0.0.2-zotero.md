# QA: v0.0.2 Zotero

Issues #12–#15: encrypted per-user key, Zotero client and browse, append-only add to the bibliography, and the editor
panel. Automated: `e2e/zotero.spec.ts` (fake Zotero), `integrations` unit tests.

**Needs, either:**
- **A real Zotero account** with a few items (at least one with an unusual title, one in a group library if you can) and an
  API key from https://www.zotero.org/settings/keys/new with library read access (and group read access); or
- **The fake Zotero**: `ZOTERO_API_BASE=http://localhost:9099 docker compose up -d api`, then
  `docker compose exec -d api python -m integrations.devserver 9099`. Any API key works. Restart the api without the
  override when done.

Also an **Owner** account, a project with a `main.tex`, and a **Guest** invite link for part E.

## A. Connect

| # | Step | Expected |
|---|---|---|
| 1 | Editor → right rail → **Zotero** | A connect screen asking for a Zotero API key, with a link to create one |
| 2 | Enter a wrong key, press **Connect** | A clear error; nothing is stored |
| 3 | Enter the right key, press **Connect** | The panel shows your Zotero username and the key's last four characters only |
| 4 | Reload the page and reopen the panel | Still connected; the full key is never shown |
| 5 | Developer tools → Network: look at the responses of `/api/integrations/zotero` | No response contains the full key |

## B. Browse and insert a citation

| # | Step | Expected |
|---|---|---|
| 1 | Pick your library (and a group, if you have one), then a collection | Items load, at most 50 per page, with paging if there are more |
| 2 | Type in **Search** (e.g. a word from a title) | The list narrows to matching items |
| 3 | Put the caret in `main.tex`, select an item, press **Insert \cite{}** | `\cite{<key>}` appears at the caret |

## C. Add to the bibliography

| # | Step | Expected |
|---|---|---|
| 1 | In a project with **no** `.bib` file, select an item, press **Add to bibliography** | `references.bib` is created with the entry, under a `% zotero: <library>:<itemKey>` comment; the status says "1 added to references.bib" |
| 2 | Press **Add to bibliography** again for the same item | The status says it is already there (e.g. "0 added to references.bib, 1 already there."); the file is not changed |
| 3 | Add a second item | It is appended; nothing above it changed (check with the editor or the compile) |
| 4 | Make a project with one `.bib` named `refs.bib` and add an item | It goes into `refs.bib` |
| 5 | In a project whose `.tex` uses `\usepackage{biblatex}`, add an item | The entry is biblatex style (e.g. `@article` with `date =`) |
| 6 | Cite the new key in `main.tex` with a `\bibliography{references}` and compile | The reference appears in the PDF |

## D. Files open live

| # | Step | Expected |
|---|---|---|
| 1 | Turn on live editing (Collaboration panel), open `references.bib` in the editor, then add an item from the panel | The entry appears in the open document at once and is kept after a save and reload (it was written through the live document) |
| 2 | With `main.tex` open live and `references.bib` open live in a second browser, add an item | You are told to open the file, or the entry is appended through the live document; it is never silently lost |

## E. Who can use it

| # | Step | Expected |
|---|---|---|
| 1 | Open the project as a **Guest** (invite link in a private window) | No Zotero tool, or it refuses: guests have no Zotero connection |
| 2 | Back as Owner: **Disconnect** | The panel goes back to the connect screen; browsing fails until you connect again |
