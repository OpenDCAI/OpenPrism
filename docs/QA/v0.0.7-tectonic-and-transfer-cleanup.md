# QA: v0.0.7 Tectonic and failed-transfer cleanup

Issues #40 (Tectonic compiles offline from a bundled TeX Live 2022) and #41 (a failed template transfer deletes the
unfinished project it created). Automated: `e2e/compile-target.spec.ts` (Tectonic test), `e2e/transfer-layout-check.spec.ts`
(failed-transfer test), `jobs.tests.TectonicTests`, `BuiltinTemplateTests.test_every_builtin_template_compiles_with_tectonic`,
`transfer` tests.

**Needs:**
- The **rebuilt** worker image: `docker compose build worker-tex && docker compose up -d`. The first build downloads a
  2.9 GB package bundle and takes several minutes; later builds reuse it.
- An **Owner** account with the built-in templates loaded (see README), and a working AI model for part C (the `.env`
  `OPENPRISM_LLM_*` values or your browser AI settings), plus a **wrong** API key to hand.

## B. Compiling with Tectonic (#40)

| # | Step | Expected |
|---|---|---|
| 1 | Open a project, **Compile options** (arrow next to **Compile PDF**) → **Tectonic** | Tectonic is ticked; the choice survives a reload |
| 2 | **Compile PDF** | The PDF appears within a few seconds; the status bar names tectonic; the log starts with `note: Running TeX ...` and mentions no downloads |
| 3 | Create a project from each built-in template (**ACL, arXiv, CVPR, ICML, NeurIPS**) and compile each with Tectonic | Every one produces its PDF |
| 4 | Add a `refs.bib` with one entry, cite it with `\cite{…}`, `\bibliographystyle{plain}`, `\bibliography{refs}`, compile | The citation and the reference list appear (tectonic runs bibtex itself) |
| 5 | Put the caret on a paragraph in the middle of a long document, compile | The PDF preview scrolls to that paragraph, as with pdfLaTeX |
| 6 | Add `\usepackage{nosuchpackage}` and compile | Fails at once (not after a timeout); the error reads "nosuchpackage.sty is not in the offline package bundle tectonic uses." and the log is shown |
| 7 | A document with `\usepackage{biblatex}`, `\addbibresource{refs.bib}`, `\printbibliography` | Fails with "Tectonic cannot run biber here. Compile biblatex documents with pdfLaTeX, XeLaTeX or LuaLaTeX." Switching to pdfLaTeX compiles it |
| 8 | `\immediate\write18{touch /tmp/pwned}x` in the body, compile; then `docker compose exec worker-tex ls /tmp/pwned` | The compile runs; the file does not exist (shell escape is off) |
| 9 | Switch back to **pdfLaTeX** and compile | Works as before |

**Offline (acceptance check):** with no network at all, every template still compiles:

```bash
docker run --rm --network none --read-only --tmpfs /tmp -v "$PWD/templates:/t:ro" --entrypoint bash openprism-worker-tex -c \
  'cp -r /t/acl /tmp/w && cd /tmp/w && env -i PATH=/opt/tectonic/bin HOME=/tmp TECTONIC_CACHE_DIR=/opt/tectonic/cache \
   tectonic --untrusted --bundle /opt/tectonic/bundle acl_latex.tex && ls *.pdf'
```

Expected: `acl_latex.pdf`. Repeat with `arxiv`/`template.tex`, `cvpr`/`main.tex`, `icml`/`main.tex`, `neurips`/`main.tex`.

## C. A failed transfer removes its project (#41)

| # | Step | Expected |
|---|---|---|
| 1 | Note the projects in the list. Put a **wrong API key** in your AI settings (and make sure no workspace AI provider is set) | |
| 2 | A project's **More actions** → **Transfer**, target **ACL**, **Start Transfer** | Progress lines appear; soon the transfer fails with the model's error, and below it "The unfinished project was removed." |
| 3 | Look at the project list (no reload) | No new half-made project is left; the list is as in step 1 |
| 4 | Fix the key and transfer again | It finishes; the new project stays and opens normally |
| 5 | (Optional, takes an hour) Start a transfer with **Enable layout check (VLM)**; close the tab while it says it is checking the layout | About an hour later (`JOB_WAITING_STALE_MINUTES`, 60) the half-made project is gone from the list. Before v0.0.7 it stayed forever |
