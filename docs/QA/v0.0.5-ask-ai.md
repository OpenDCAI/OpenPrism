# QA: v0.0.5 Ask AI in place

Issues #27–#31: Ctrl/Cmd+K opens a request bar; the AI proposes changes with the editor's context; you review and apply them
as one undo step; stale proposals are refused; progress, cancel, rate limit, recall. Automated: `e2e/ai-command.spec.ts`
(model stubbed), `ai/test_edit_tasks.py` (replayed model, real compile), `ai/tests.py`.

**Needs:** a **real model** (the `.env` `OPENPRISM_LLM_*` values, a workspace provider, or your browser AI settings),
**Owner** and a **Viewer** in the same workspace, projects from the **ACL**, **NeurIPS**, **ICML** and **CVPR** templates,
and two browsers for part E. Mac testers use Cmd where the script says Ctrl.

## A. Opening and closing the bar

| # | Step | Expected |
|---|---|---|
| 1 | Click in the editor, press **Ctrl+K** | A bar opens over the editor with the cursor in its input; the placeholder suggests tasks |
| 2 | Press **Esc** | The bar closes and the caret is back in the editor where it was |
| 3 | Toolbar → **Ask AI** (wand icon); hover it first | The tooltip shows the shortcut; the bar opens |
| 4 | **Insert** menu → **Ask AI…** | The bar opens |
| 5 | Select a few words, press Ctrl+K | The placeholder asks what should change in the selection |
| 6 | Resize the window to phone width (~390 px) and open the bar | The input stays usable; buttons wrap below it rather than squeezing it |
| 7 | With a Chinese/Japanese IME, compose text in the bar and press Enter to pick a candidate | Enter picks the candidate; it does not send the request |

## B. Tasks on real templates (real model)

For each template, put the caret near the top of the document, press Ctrl+K and send the request. Expect a reply within
about 5–40 s, with progress lines ("Thinking…", "Reading …") in the bar meanwhile.

| # | Template | Request | Expected |
|---|---|---|---|
| 1 | ACL | `Add an author: Ada Lovelace, Analytical Engine Lab, ada@example.org` | The Diff preview opens with a change to `acl_latex.tex`'s `\author{…}` block in ACL's style (`\\` lines, `\texttt{}` e-mail); no unrelated lines touched |
| 2 | NeurIPS | same | Edits NeurIPS's `\author{… \\ …}` |
| 3 | CVPR | same | Edits CVPR's author block (`{\tt\small …}` e-mail) |
| 4 | ICML | same | Edits ICML's author block |
| 5 | any | `Create a new section on related work, placed before the conclusion` | A `\section{Related Work}` in the right place, or (CVPR) a new `sec/…` file plus an `\input` in `main.tex`: both appear in the Diff preview |
| 6 | NeurIPS | Type an `itemize` list with three `\item key: value` lines, select it, ask `turn this list into a table` | The selection becomes a `tabular`/`table`; nothing else changes |
| 7 | any | After applying 1–6, **Compile PDF** | Each edited project still compiles and shows the change |
| 8 | any | Ask something that needs no change (`what does this file do?`) | The bar shows the model's answer; no Diff preview opens |

Write down any proposal that touched unrelated text or broke the compile; that is a finding.

## C. Review, apply, undo, reject

| # | Step | Expected |
|---|---|---|
| 1 | Get a proposal (any task) | Nothing has changed in the editor yet; the Diff preview shows the change side by side |
| 2 | **Apply change** | The editor shows the change; the status bar says it was applied |
| 3 | Click in the editor, **Ctrl+Z** once | The whole AI change is undone in one step, exactly back to the earlier text |
| 4 | Get a multi-file proposal (B5 on CVPR), **Apply all** | The new file appears in the file tree with its content; the main file has the `\input` |
| 5 | Get another proposal, **Discard** | Nothing changes in any file |

## D. Stale proposals

| # | Step | Expected |
|---|---|---|
| 1 | Ask to change one specific line (e.g. "make the title longer"); while it runs, edit that same line yourself | When the proposal arrives, **Apply change** is refused: "The file changed after this was proposed, so it no longer applies. Ask again." Your edit is kept |
| 2 | Ask again to change the title; while it runs, edit a paragraph further down | Applying works and keeps your paragraph edit |

## E. Live session (two browsers)

| # | Step | Expected |
|---|---|---|
| 1 | Owner: Collaboration panel → create an invite link (turns live editing on); open the link in a private window (**Guest**) on the same file | Both connected |
| 2 | Guest: no **Ask AI** button; Ctrl+K does nothing in the editor | Guests never get the bar |
| 3 | Owner: ask for a change, apply it | The Guest sees the change appear within a second or two; the Guest's other text is untouched |
| 4 | Owner: ask for a change to a line; Guest edits that line while it runs; Owner applies | Refused as stale; the Guest's edit stays |
| 5 | Owner: Ctrl+Z after an applied change, while the Guest is typing elsewhere | Only the AI change is undone; the Guest's typing is not (if the Guest's text is undone too, that is a known backlog item: note it) |

## F. Progress, cancel, limits, recall

| # | Step | Expected |
|---|---|---|
| 1 | Send a larger task (e.g. "add a related work section with three paragraphs") | The bar shows progress lines that change as the AI reads files |
| 2 | Press **Cancel** while it runs (or Esc) | "Cancelled."; no Diff preview opens later even if the model finishes; the bar is usable again |
| 3 | Send 21 requests within one minute (short ones like `say ok`) | The 21st shows "Too many AI requests. Try again in a minute." (limit `AI_EDIT_RATE_PER_MINUTE`, default 20). After a minute it works again; the Assistant panel is not limited |
| 4 | Open the bar with an empty input and press **Up** a few times, then **Down** | Earlier requests come back newest first; Down walks back to an empty input |
| 5 | Reload the page and press Up in the bar | The recent requests survive the reload (they are kept in this browser only) |
