# QA: v0.0.3 Workspace AI provider (and v0.0.3.1 build fix)

Issues #16–#19: encrypted workspace LLM config, used by the AI features before the browser's key, admin settings, editor
notice. #20: the web image builds. Automated: `e2e/workspace-ai-provider.spec.ts`, `e2e/workspace-provider-notice.spec.ts`,
`integrations` and `ai` tests.

**Needs:** a team workspace "QA Lab" with **Owner**, **Editor** and **Viewer** (see README), a project "Lab paper" in it, and a
real LLM endpoint, model and key (the values in `.env` work). Have a second, wrong key ready for step B5.

## A. Settings (Owner / admin)

| # | Step | Expected |
|---|---|---|
| 1 | As Owner, workspace **Settings** → **AI provider** | "No workspace AI provider is set…" and a form: **Endpoint**, **Model**, **API key**. **Save** is disabled until it is filled |
| 2 | Fill all three, **Save** | "AI provider saved"; the key is shown only as "ending NNNN" |
| 3 | Reload | The endpoint and model are kept; the key is still only "ending NNNN" |
| 4 | Change only **Model**, **Save** | Saved; the key is unchanged (still the same last four) |
| 5 | **Replace key**, enter a new key, **Save** | The last four change |
| 6 | Set **Endpoint** to `http://169.254.169.254/latest`, **Save** | Refused with a message about a non-public address; the old settings stay |
| 7 | Developer tools → Network on this page | No response contains the full key |

## B. Who uses it

| # | Step | Expected |
|---|---|---|
| 1 | As **Editor**, open **Settings** → **AI provider** | Read-only status naming the model; no buttons |
| 2 | As Editor, clear your own browser AI settings (account menu → **AI & search settings**), open "Lab paper", use the **Assistant** (Chat) | It answers, using the workspace provider. The AI settings dialog says the workspace provider is used and names the model |
| 3 | As Editor, put a different key in your browser AI settings and ask again | Still answered by the workspace provider (it wins over the browser key) |
| 4 | As **Viewer**, open "Lab paper" and the AI settings dialog | No workspace-provider notice; a viewer's AI requests use their own browser key or the server default |
| 5 | As Owner, replace the workspace key with a wrong one; as Editor, ask the Assistant | A clear provider error, not a hang; fix the key again afterwards |
| 6 | As Editor, open a project in your **Personal** workspace and ask | It uses your browser key (the provider belongs to "QA Lab" only) |
| 7 | Run a **Websearch** and a **Vision** request (paste an image of an equation) in "Lab paper" as Editor | Both work through the workspace provider |
| 8 | Start a **Template transfer** of "Lab paper" | The transfer's LLM calls use the target workspace's provider |

## C. Remove

| # | Step | Expected |
|---|---|---|
| 1 | As Owner, **Remove** and confirm | "AI provider removed"; the form is empty again |
| 2 | As Editor, ask the Assistant | It uses the browser key again (or the server default) |
