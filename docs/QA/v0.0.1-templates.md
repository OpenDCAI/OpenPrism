# QA: v0.0.1 Templates

Issues #8 (built-in and uploaded templates have a compilable main file) and #9 (template transfer layout check finishes from
the UI). Automated: `e2e/builtin-templates.spec.ts`, `e2e/transfer-layout-check.spec.ts`, `BuiltinTemplateTests`.

**Needs:** an account with the built-in templates imported (see README). For part C, an LLM configured (browser AI settings,
workspace provider, or the server's `OPENPRISM_LLM_*`). The layout check also needs a vision-capable model.

## A. Every built-in template compiles

For each template **ACL, arXiv, CVPR, NeurIPS, ICML**:

| # | Step | Expected |
|---|---|---|
| 1 | Projects → new project → pick the template → create | The editor opens on the template's main file: `acl_latex.tex` for ACL, `template.tex` for arXiv, `main.tex` for the others |
| 2 | Look at the file tree | The main file is there; for CVPR also `preamble.tex` and the `sec/` files |
| 3 | Press **Compile PDF** | The status bar shows progress, then the PDF appears in the preview. No "file not found" error |
| 4 | Open the compile log | No fatal errors (warnings are fine) |

## B. Uploaded templates

| # | Step | Expected |
|---|---|---|
| 1 | Make a zip of a small template whose main file is **not** called `main.tex` (e.g. `paper.tex` with `\documentclass`, plus a `.sty`) | |
| 2 | In the template gallery, upload the zip | The template appears in the list |
| 3 | Create a project from it | The editor opens `paper.tex` (the detected main file) |
| 4 | Compile | A PDF appears |
| 5 | Upload a zip with two root-level `.tex` files (no `main.tex`), only one containing `\documentclass` | That one is chosen as the main file (rule: `main.tex` if present, else the first root-level `.tex` with `\documentclass`) |

## C. Template transfer with the layout check

| # | Step | Expected |
|---|---|---|
| 1 | Projects list → a project's **More actions** menu → **Transfer** | The transfer panel opens |
| 2 | Choose **Classic mode**, target template **ACL**, tick **Enable layout check (VLM)**, press **Start Transfer** | Progress lines appear and keep updating |
| 3 | Wait for the pause at the layout check | The panel renders the compiled PDF's pages (you may see "rendering pages"), sends them and carries on without you doing anything |
| 4 | Wait for the end | Status success; a new project in the ACL template exists and opens; its PDF is downloadable |
| 5 | Repeat with a model that has no vision support, or with the network to the LLM blocked during the pause | The run does not hang at the layout check. If the pages cannot be rendered you see a warning that the layout check was skipped, and the transfer continues |
| 6 | Start a transfer and close the tab during the pause, then reopen the project list | No crash; the job ends (failed or finished) rather than staying "running" forever (the reaper fails idle jobs after 10 minutes) |
