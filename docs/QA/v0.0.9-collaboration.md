# QA: v0.0.9 Collaboration enhancements

Issues #54 (changes made outside live editing reach open editors), #55 (renaming or deleting an open file) and #56 (no
edits lost when a server process crashes; cursors of a crashed server expire).
Automated: `e2e/collab-live.spec.ts`; API tests `collab.tests.LiveWriteTests`, `collab.tests.FileGoneTests`,
`collab.tests.CrashTests`.

**Needs:**
- `docker compose up -d --wait`, then `docker compose restart worker-tex worker-ai beat` (new beat task).
- An **Owner** account with a project containing `main.tex` and `intro.tex`.
- A **second browser profile** (or a private window) for a guest: in the editor's *Collaborate* panel create an
  **Editor** invite link and open it there. The guest is always in live mode; call this window **Guest**, the owner's
  window **Owner**. The Owner's tab is *not* live unless the steps say so.

## A. Changes made outside live editing (#54)

| # | Step | Expected |
|---|---|---|
| 1 | Guest: open `main.tex`, wait until the Collaborate panel shows *Connected* | |
| 2 | Owner: on your computer, make a copy of `main.tex` with one sentence changed; in the file tree use *Upload files* and pick it | Within a few seconds the Guest's editor shows the changed sentence, without a reload |
| 3 | Guest: type a line at the end; wait 3 s; reload the Guest window | Both the uploaded sentence and the typed line are there |
| 4 | Owner: open `main.tex`, change a word and save (Ctrl/Cmd+S) | Guest sees the change within a few seconds |
| 5 | Guest: type near the top while the Owner, at the same moment, changes a word near the bottom and saves | Both edits end up in the file; nothing is lost or duplicated |
| 6 | Owner: *Convert template* (or *Apply template*) on the project while the Guest has `main.tex` open | Guest's editor shows the converted text; after 3 s and a reload it is still the converted text |

## B. Renaming and deleting an open file (#55)

| # | Step | Expected |
|---|---|---|
| 1 | Guest: open `intro.tex` and type a few words, then immediately (within a second) Owner: rename `intro.tex` to `chapter1.tex` | Guest's editor switches to `chapter1.tex`, the status bar says "intro.tex was renamed to chapter1.tex", and the words just typed are there |
| 2 | Wait 30 s; reload both windows | There is no `intro.tex` in the tree; `chapter1.tex` has the typed words |
| 3 | Guest: open `chapter1.tex`. Owner: delete it | Guest's status bar says "chapter1.tex was deleted" and the editor shows `main.tex` |
| 4 | Wait 30 s; reload | `chapter1.tex` has not come back |
| 5 | Guest: open a file inside a folder. Owner: rename the folder | Guest follows the file into the renamed folder |
| 6 | Owner: create a new file with the name of the file deleted in step 3, with different text; Guest: open it | Guest sees only the new text |

## C. Server crashes (#56)

| # | Step | Expected |
|---|---|---|
| 1 | Guest: open `main.tex`, type a distinctive word, and **at once** run `docker compose kill -s KILL api`; then close the Guest window | |
| 2 | `docker compose up -d --wait api`; within about 2.5 minutes look at `main.tex` (Owner, reload) | The distinctive word is there (saved by the beat task `collab.tasks.recover_update_logs`; `docker compose logs worker-ai` shows it succeeded with `1`) |
| 3 | Run a second api replica: `docker compose run -d --no-deps -p 8001:8000 api uvicorn config.asgi:application --host 0.0.0.0 --port 8000`. Guest 1 opens the app through :5173, Guest 2 through a dev server pointed at :8001 (or use `apps/api/collab/interop/yjs_client.mjs`) | Both see each other's cursor |
| 4 | Kill the second replica's container with `docker kill` | Within ~35 s the cursor of the guest on that replica disappears for the other guest |
| 5 | `docker compose exec redis redis-cli keys 'collab:log:*'` while nobody is typing | Empty, or only lists of a few entries that disappear after the next save |
